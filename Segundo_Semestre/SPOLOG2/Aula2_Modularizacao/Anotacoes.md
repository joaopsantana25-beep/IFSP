#Modularização

Modularização é a prática de dividir cada parte de um programa em  pastas separadas para ficar mais organizado e fácil de trabalhar. Cada parte resolve um problema específico e dentro dela cabe o conceito de POO (Programação Orientada a Objetos).

Dentre as vantagens estão:
->Reutilização
->Facilidade de manutenção
->Trabalho em equipe
->Escalabilidade

Existe um conceito dentro de POO que é conhecido como SOLID que é o acronomo de 5 princípios de design de código:

->S - Princípio da Responsabilidade Única: Uma classe deve ter um e apenas um motivo para mudar, o que significa que ela deve possuir apenas uma atribuição ou tarefa principal.

->O - Princípio Aberto/Fechado: As entidades de software devem estar abertas para extensão, permitindo novos comportamentos, mas fechadas para modificação do código já existente.

->L - Princípio da Substituição de Liskov: Objetos de um tipo base devem poder ser substítuidos por objetos de seus subtipos sem quebrar o funcionamento correto do programa

->I - Princío da Segregação de Interfaces: É melhor criar várias interfaces especifícas para cada cliente do que uma única interface genérica e gigante que obrigue classe a implementarem métondos que não utilizam.

->D - Princípio da Inversão de Dependência: Depende de abstrações e não de implementações concretas; módulos de alto nível não devem depender de módulos de baixo nível, ambos devem depender de interfaces.
